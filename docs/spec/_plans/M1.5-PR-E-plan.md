## 1. Goal

After this PR lands:

- Two more vendors plug into PR-D's `SensorConnector` Protocol with no Protocol changes — proving the abstraction generalizes.
- **Davis WeatherLink v2** — API-key + secret paste; 15-min polling; LW reported 0–15 → normalized to minutes per hour; rate-limit aware (1,000 calls/hr account-wide).
- **METER ZENTRA Cloud v4** — bearer-token paste *plus* native HTTPS Push API (formdata POST). Webhook-first per spec §12A.4: a publicly addressable receiver endpoint accepts pushes, validates HMAC + tenant binding, and writes SensorReading rows in real time. Polling fallback covers gaps.
- Both vendors register via `@register("davis")` / `@register("meter")` decorators; the Pessl polling task pattern is generalized into a vendor-agnostic `sensor_pull` task that takes a slug.
- Frontend: `/spray/integrations` gains "Connect Davis" + "Connect METER" buttons that open paste-key dialogs (no OAuth round-trip). Validation hits a smoke endpoint before saving.
- ~50 new tests across credential paste, polling, webhook receiver, normalizer variants, schema-drift handling.

This PR does NOT wire:
- Sencrop OAuth (Phase 2 per spec §12A.2).
- Pessl HMAC-SHA256 single-account fallback (still deferred from PR-D).
- Sensor-fed `WeatherWindow` enrichment for ensemble runners (PR-E.5 / PR-D.5).
- METER v5 (2026 release; v4 ships now per spec §12A.1).

## 4. Architecture

### 4.1 Namespace additions

```
services/api/spray/connectors/sensors/
├── pessl/                          # PR-D
├── davis/                          # NEW
│   ├── __init__.py
│   ├── client.py                   # API-Key + Secret HTTP wrapper
│   ├── connector.py                # SensorConnector implementation
│   └── normalizer.py               # Davis payload → canonical schema (LW 0-15 → min)

    └── normalizer.py               # METER payload → canonical schema
```

### 4.2 Polling task generalization (Q9)

`services/worker/graft_worker/tasks/sensor_pull.py` (new):

- `pull_all_sensor_stations(vendor_slug)` — fans out per active station for a given vendor.
- `pull_sensor_station(station_id, vendor_slug)` — vendor-agnostic per-station pull. Reuses PR-D's gap-fill rule, idempotent upsert, lake-event emit.

Beat schedule registers two new entries: `davis-pull` (every 15 min) and `meter-pull` (every 60 min). The existing `pessl-pull` keeps its dedicated entry but its body becomes:

```python
@shared_task(...)
def pull_all_pessl_stations():
    return pull_all_sensor_stations("pessl")
```

### 4.3 New paste-key onboarding endpoints

| Method | Path | Notes |
|---|---|---|
| `POST` | `/orgs/<org>/integrations/davis/connect` | Body: `{api_key, api_secret, label?}`. Validates via Davis `/v2/stations` smoke call before save. |
| `POST` | `/orgs/<org>/integrations/meter/connect` | Body: `{token, label?}`. Validates via METER `/api/v1/readings/` smoke. Also generates + returns `webhook_secret` (one-time response). |

Both reuse PR-D's `IntegrationConnection.token_ciphertext`. Davis blob shape: `{api_key, api_secret}`. METER blob shape: `{token, webhook_secret}`.

### 4.4 METER webhook receiver

`services/api/spray/views.py` adds `MeterWebhookView`:

```
POST /api/spray/integrations/meter/webhook
```

- Public path (Clerk middleware allowlist).
- Reads raw body bytes + `X-MET-Signature` header.
- Looks up the IntegrationConnection by `device_sn` from the payload (via SensorStation.vendor_station_id).
- Decrypts the token blob, computes `HMAC-SHA256(body, webhook_secret)`, compares constant-time.
- On valid: normalizes payload → upserts SensorReading rows → emits `sensor.reading_pulled` events → 202 Accepted.
- On invalid HMAC, unknown device, or replay: 400/403/409 with no row write.

### 4.5 Webhook idempotency (Q10)

Same `(station, ts)` unique upsert. METER push retries that include the same timestamps are absorbed silently. The receiver returns 202 even on full-duplicate to avoid encouraging retry storms.

### 4.6 Frontend additions

- `components/spray/PasteKeyDialog.tsx` — generic two-field paste dialog, props `{vendor, fields[]}`.
- `app/spray/(app)/integrations/page.tsx` — add Davis + METER cards next to the existing Pessl card; click → open `PasteKeyDialog` → POST connect → on 200, refresh list. METER variant shows the returned `webhook_secret` once with a "Copy" button + paste-into-METER instructions.
- `app/spray/(app)/integrations/[conn_id]/page.tsx` — already vendor-agnostic from PR-D; no changes needed beyond surfacing the (per-vendor) station-list shape.

### 4.7 Lake event schema additions

No new event categories needed — `sensor.reading_pulled.v1` and `integration.connected.v1` / `integration.disconnected.v1` from PR-D already cover Davis + METER (their `vendor` enum already includes both slugs).

One new event: `sensor.webhook_received.v1` — emits on every accepted METER push for audit, regardless of how many readings it contained. Fields: `org_id, connection_id, vendor, payload_size_bytes, reading_count, accepted_at`.

## 7. Risks

| ID | Risk | Mitigation |
|---|---|---|
| E1 | **METER webhook public path → DDoS / spam.** | HMAC validation rejects unsigned requests fast; Cloudflare in front of Render absorbs L4 noise (already on); rate-limit per source IP at view layer. |
| E2 | **Davis 1,000-call/hr limit shared across the entire account.** Multi-org Davis users could starve each other. | Track per-account call count in Redis (`davis:account:<key_hash>:hour:<bucket>`); back off + log when ≥80% utilized; surface "Tier upgrade recommended" banner in the integrations UI. |
| E3 | **METER v5 release breaks v4 endpoints (2026).** | Pin v4 in `_api_base()`; integration test against v4 fixture; prep v5 adapter as PR-E.1 when Pessl-style migration is needed. |
| E4 | **HMAC secret leak via logs.** | `webhook_secret` is encrypted in token_ciphertext; `redact()` from PR-D's credentials helper covers it. Never logged in raw form, never re-displayed in the UI after the one-time reveal. |
| E5 | **Davis LW 0-15 mis-conversion.** Industry pitfall: some apps treat 0-15 as "0-15 minutes", others as "out of 15 = wet for the whole hour". Spec §12A.1 calls out the bug. | Conversion tested explicitly against multiple values; assertion in normalizer that `lw_value > 15` raises a warning (impossible value implies new sensor model or schema drift). |
| E6 | **METER ATMOS-41 has no native LW (PHYTOS-31 add-on required).** | Normalizer falls back to `leaf_wetness_min = None` if no LW channel present; SensorReading still persists with the other fields; ensemble layer (PR-C) reads `quality_flag` to weight accordingly. |
| E7 | **Webhook arrives before poll's first backfill** — race where push lands a reading for a station that has no `last_seen_at` yet. | Idempotent upsert on `(station, ts)` makes the order of arrival irrelevant; `last_seen_at` advances to whichever arrives later. |
