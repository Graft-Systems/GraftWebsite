## 1. Goal

After this PR lands:

- A **two-path daily-brief renderer**: LLM-authored prose when verification passes, deterministic-template fallback (PR-F's `render_brief`) when it fails. Same envelope shape; the `renderer` field tells the UI which path was used.
- **P-Cite verifier**: every numeric claim in the LLM output must trace back to a verified source — either a `[citation_id]` resolvable via `sources_master.csv` *and* present in the verdict's `drivers`, or one of the schema-validated numeric fields on the verdict itself (severity, confidence, urgency). Any numeric token in the LLM prose that doesn't satisfy this check trips the **hallucination guard** and forces fallback to deterministic.
- **Anthropic Claude API** as the LLM provider (Benson already has access; cleanest path; no new vendor relationship). Model: `claude-sonnet-4-5` (Sonnet for the prose generation; Opus is overkill for paragraph-form prose with tight constraints). Token budget: ≤2,000 input + ≤800 output per brief, capped at $0.05/brief at current Anthropic pricing.
- **PDF audit export**: new endpoint `GET /verdicts/<id>/audit.pdf` returns a tamper-evident PDF showing the verdict, the brief (LLM or fallback), the full driver list with citations, the audit_hash, and a generation timestamp. Suitable for grower record-keeping + compliance (e.g. CDPR PUR).
- A new **`fallback_reason`** taxonomy on the brief envelope: `null` when LLM path succeeded, one of `{llm_disabled, llm_unavailable, llm_timeout, hallucination_guard_failed, citation_missing, schema_mismatch, prose_too_long}` otherwise.
- Frontend updates: `VerdictCard` gets an "audit-log PDF" download link in the footer, plus a small `renderer` indicator (one of `llm` / `fallback`) so growers know which path served the brief.
- Lake event: `brief.rendered.v1` emitted per render, capturing renderer path, fallback_reason, latency_ms, and prompt+response token counts (for cost telemetry — payload + content not stored).
- ~40 new tests across hallucination guard, citation verifier, fallback paths, PDF generation, end-to-end LLM happy path (mocked).

This PR does NOT wire:
- Streaming LLM responses to the UI (Phase 2 — the deterministic brief renders instantly anyway, prose can wait 2-3 seconds).
- Multi-language briefs (EN-US only at MVP; ES + FR land with PR-H advisory feeds).
- Email-as-IO delivery of the brief (AgentMail commitment but post-MVP per Q17 resolution).
- Per-grower brief tone customization (formal vs casual — Phase 2).
- LLM-authored split-summary or driver explanations (PR-F.5.1; this PR keeps the LLM scope to the prose paragraphs only, not the structured fields).

## 4. Architecture

### 4.1 Two-path renderer

`spray/recommendation/daily_brief.py` (PR-F) keeps its current `render_brief()` as the deterministic fallback. New module:

```
services/api/spray/recommendation/
├── citations.py            # PR-F (unchanged)
├── daily_brief.py          # PR-F (renamed: render_deterministic_brief)
├── llm_brief.py            # NEW — Anthropic-backed prose generator
├── verifier.py             # NEW — P-Cite + hallucination guard
└── orchestrator.py         # NEW — picks LLM, falls back deterministic
```

Public API stays at `render_brief(verdict)` (now in `orchestrator.py`). Existing PR-F callers don't change.

### 4.2 Orchestrator decision tree

```
render_brief(verdict):
    if not settings.LLM_BRIEF_ENABLED:
        return render_deterministic_brief(verdict, fallback_reason="llm_disabled")

    cache_key = f"brief:{verdict['audit_hash']}"
    if cached := cache.get(cache_key):
        return cached

    try:
        prose = llm_brief.generate(verdict, timeout=10)
    except LLMUnavailable:
        return render_deterministic_brief(verdict, fallback_reason="llm_unavailable")
    except LLMTimeout:
        return render_deterministic_brief(verdict, fallback_reason="llm_timeout")

    verdict_result = verifier.verify(prose, verdict)
    if not verdict_result.ok:
        return render_deterministic_brief(verdict, fallback_reason=verdict_result.reason)

    envelope = _llm_envelope(prose, verdict, verdict_result)
    cache.set(cache_key, envelope, ttl=3600)
    return envelope
```

### 4.3 LLM prompt template

Pinned, versioned, in-repo at `spray/recommendation/prompts/daily_brief_v1.md`. Schema:

```
SYSTEM: You write daily disease-pressure briefs for a winegrower. Cited drivers.
        No invented numbers. Reference only the verdict provided.

USER:   <verdict JSON, schema-validated>
        Drivers: <flattened list with [citation_id] markers>
        Constraint: ≤4 paragraphs, ≤120 words total, plain English.
        Every number in your output MUST appear verbatim in the verdict
        provided. Cite drivers via [citation_id] markers exactly.
```

Prompt version is part of the audit trail. Bumping it requires a new schema file + plan revision (per spec §13B.3 LLM-content-version is auditable).

### 4.4 P-Cite verifier algorithm

1. Tokenize LLM output into numeric atoms (regex: `\d+(?:\.\d+)?(?:%|°C|/10)?`).
2. For each atom, check membership in:
   - Verdict severity fields (`powdery_severity_1_10`, `downy_severity_1_10`, `*_confidence`)
   - Driver `value` / `threshold` fields
   - Forecast 7d severities
3. For each `[citation_id]` marker in the LLM output:
   - Verify it resolves via `citations.lookup` (PR-F)
   - Verify it appears in `verdict.drivers[].citation_id`
4. Soft check: prose ≤ 600 chars (configurable). Long prose → `prose_too_long` reason.

Returns `VerifyResult(ok: bool, reason: str | None, unverified_atoms: list[str], unknown_citations: list[str])`.

### 4.5 PDF audit export

`spray/recommendation/pdf_audit.py` (NEW). Uses `reportlab.platypus` to compose:

- **Header**: Block name, date, region, generated_at, audit_hash (8-char prefix display, full hash in footer).
- **Section 1**: Verdict — action chip (color-coded), urgency label, severity bars (rendered as horizontal bars).
- **Section 2**: Brief — headline + paragraphs verbatim from envelope.
- **Section 3**: Drivers table — model, value, threshold, weight, citation marker.
- **Section 4**: Citations — full bibliographic entries from `sources_master.csv`.
- **Section 5**: Audit footer — full audit_hash, model_versions JSON, renderer, fallback_reason.

Endpoint: `GET /api/spray/orgs/<org>/blocks/<block>/verdicts/<verdict>/audit.pdf` returns `application/pdf` inline.

## 7. Risks

| ID | Risk | Mitigation |
|---|---|---|
| F1 | **LLM hallucinates a number** that happens to match a verdict number by coincidence (e.g. LLM says "65%" but verdict has 0.65 confidence). | Verifier matches numeric atoms exactly to verdict-derived strings, not approximate-equal. False-positive rate dropped further by requiring atom to appear in *one specific* verdict field, not any field. |
| F2 | **LLM provider outage** during high-traffic windows (e.g. Friday afternoon spray decisions). | Deterministic fallback always works. Lake telemetry tracks fallback rate; ≥5% triggers Slack alert + a planned migration to a secondary provider. |
| F3 | **Cost overrun** if every dashboard load fans out a Claude call. | 1-hour cache keyed on audit_hash; concurrency semaphore caps in-flight calls per dyno. Spend telemetry per org via `brief.rendered.v1` event. |
| F4 | **Prompt drift** — small wording changes in the system prompt break the verifier or change the prose tone unexpectedly. | Prompt is in-repo, versioned, included in audit trail. Changing it requires a new prompt-version + plan revision. |
| F5 | **PDF tampering risk** — grower edits the PDF then re-shares. | Audit footer includes the full `audit_hash` plus a regeneration URL. Any verifier (us, third-party auditor) re-fetches the PDF and confirms hashes match. |
| F6 | **reportlab CVE** drift over time. | Pin version in requirements.txt + Dependabot watches it. reportlab is widely used so patches are routine. |
| F7 | **PII leak via LLM** — verdict JSON contains org/block IDs which aren't strictly PII but are tenant data. Anthropic's data-retention policy must be on the no-training tier. | Verify Anthropic API account is on no-training tier (default for paid keys). Document in `runbooks/llm-data-policy.md`. |
| F8 | **Spec ambiguity on prose tone** — §13B.1 says LLM never originates numbers but doesn't constrain prose voice. Growers may find Claude's default tone too formal/casual. | First version uses Claude's neutral-professional default. Tone tuning is Phase 2 (Q-style customization per grower). |
